# Лабораторна робота №2 — Протокол ARP

**Дисципліна:** Тестування та контроль якості (QA) вбудованих систем  
**Студент:** Злотко Олексій, ІК-34  
**Тема:** Дослідження засобів канального рівня моделі OSI. Протокол ARP  
**Варіант QA:** №2 (останні цифри залікової книжки 08; 8 mod 3 = 2).

## Мета
Дослідити отримання MAC-адреси за відомою IPv4-адресою, ARP-кеш Linux, ARP Request/Reply, ICMP-трафік та підготувати тест-кейс для статичного ARP-запису.

## Середовище
- Windows 11, Ubuntu (WSL2);
- інтерфейс `eth0`;
- утиліти `ip`, `ping`, `tcpdump`;
- Wireshark для аналізу PCAP.

## Практичні спостереження
- У дампі `arp_capture.pcap` зафіксовано обмін ARP Request та ARP Reply між шлюзом `172.22.160.1` і вузлом `172.22.174.249`.
- Шлюз запитував MAC-адресу вузла `172.22.174.249`; у відповіді вказана MAC `00:15:5d:9d:e0:ec`.
- Зафіксовано 4 ICMP Echo Request до шлюзу; Echo Reply у цьому захопленні не виявлено.
- У таблиці сусідів є запис `172.22.160.1 → 00:15:5d:06:df:d8` зі станом `STALE`. Сам факт оновлення кешу цими двома знімками не доведений.
- Фізичний сегмент Ethernet окремо не тестувався — результати отримані у віртуалізованій мережі WSL2.
